Automation

I write the tools, not just the model

Every MEP project runs on the same handful of actions done thousands of times. None of it is difficult and none of it is where the value is — but it eats the day. So I build the tools that do it instead, and the team’s hours go to coordination.

What I build

Four languages, one reason

01

Revit add-ins in C#

Commands on the ribbon, built on the Revit API with WPF interfaces, for the jobs a drafting team repeats every week — view and graphics control, MEP routing and elevation work, coordination checks, dimensioning and tagging.

One codebase builds for every Revit release a project is on, so the team is never split across versions.

02

pyRevit and Python

The faster path for a tool that is needed this week: a script that reads the model, finds what is wrong and writes the answer back, without waiting on a build and an installer.

03

Dynamo

Where the job is a one-off piece of data work on a live model and a graph is the honest tool for it — bulk parameter work, take-offs, checks a modeller can read and adjust themselves.

04

AutoLISP

Where the work is still in AutoCAD. This is where the automation started, and it is still the right answer for a drawing office that lives in DWG.

05AI inside Revit

Where it is going: an AI platform that turns a sentence into a checked, reversible, logged change in a real model. Open source, and still in development.

How they ship

A tool a team can rely on, not a clever trick

A personal script helps one person. The difference between that and something a company can actually run on is not the code — it is everything around it.

01

An installer, not an email

The whole drafting team runs the same version of the same tools, installed the same way. Nobody is copying a file into a folder and hoping.

02

One codebase, every release

Revit changes its API between versions — units, parameters, element ids, dimensions. One codebase handles all of it, so a project on an older release is not left behind.

03

Versioned and written down

Every change has a version number and a note saying what it does. When something behaves differently from last month, there is a record of why.

04

Built around the team’s own standard

A tool that enforces somebody else’s naming is a tool nobody uses. These are built around the templates, the parameters and the conventions the team already has.

05

Reversible, and quiet about it

Anything that changes a model does it in one undo step, says plainly what it is about to do, and leaves the model in a state a person can check.
